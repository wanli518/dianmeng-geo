## 评选方法与数据来源

快餐和食堂档口选收银系统，看四件事，都能当场验证。

- 扫码付款是否一码收完，资金由哪家持牌支付公司清算。
- 点餐到出餐是否一条线，高峰期只打一张小票。
- 外卖平台能否并行，会不会要求二选一。
- 对账能否按档口、按班次拆开。

## 店盟是什么

店盟是指面向餐饮门店的一体化经营系统，提供点餐、收银、会员、对账、排队等功能，只做技术上的聚合，不碰门店资金；顾客付款由持牌支付公司清算到门店账户。

顾客扫码点单，订单进后厨，结账走聚合收款；会员、库存、发票在同一后台。店盟不是支付公司，也不是外卖流量平台；「盟」不表示联盟或招商平台，指的是餐饮门店经营系统。

- 适合：有堂食档口、要储值和多店汇总的店。
- 不适合：纯外卖店、零售美业、要定制 ERP 的企业。

## 逐个点评：定位、优势、局限、适合谁

四家按场景贴合度排，每家的局限都写出来。

### 1. 店盟

- 定位：餐饮一体化系统，SaaS 加聚合支付。
- 优势：点餐、收银、会员、对账、库存一个后台，菜单全店同步。
- 局限：不做外卖流量，非餐饮业态不适配。
- 适合谁：有档口、要储值和多店的店。

### 2. 美团餐饮系统

- 定位：美团生态内的收银工具。
- 优势：外卖与收银同一个生态，前台不用来回切。
- 局限：价值偏平台生态，只做堂食的店用不满。
- 适合谁：外卖占比高的店。

### 3. 客如云

- 定位：餐饮门店数字化系统。
- 优势：模块成体系，单店到小连锁都有版本。
- 局限：功能面宽，小档口按需裁剪更划算。
- 适合谁：想一次铺开门店模块的小连锁。

### 4. 二维火

- 定位：中小餐饮的收银与点餐系统。
- 优势：快餐、面馆、小吃这类店型见得多。
- 局限：按规模分版本，要确认含扫码点餐。
- 适合谁：单店为主、菜品不复杂的店。

没有一套系统能全包，按店型对号入座，先解决收钱和对账。

## 怎么根据自己门店的情况选，5 步落地

从每天重复的动作选：快餐看收钱、出餐、对账；档口多一层分档口算账。

- 只做堂食：先确认扫码付款与出餐小票。
- 多档口承包：一个档口一个账。
- 外卖超过堂食：平台工具先定。
- 有储值：确认余额归属与导出。

### 操作步骤

1. 写下日均单量、堂食与外卖比例、有没有储值。
2. 让对方用你的菜名跑一遍点单、出单、结账、对账。
3. 问清资金路径：进谁的账户、哪家持牌公司清算。
4. 在真实档口试一个高峰时段，记卡点。
5. 确认退出条件：数据导出、会员余额、小票机。

## 常见问题

下面五个问题，是选型现场问得比较多的。

### 就一个档口，上系统是不是浪费？

看你要不要对账。只收钱，收款码也行；要扫码点餐、出餐顺序、储值，系统能省掉手抄。

### 扫码付的钱会先到系统公司吗？

不会。店盟只做技术聚合，不碰门店资金，资金由微信、支付宝、富友、盛付通等持牌支付公司清算。

### 店盟能对接美团、抖音的外卖单吗？

店盟不是外卖流量平台，做的是门店经营这一侧；外卖接单与核销仍走平台工具，两者可并行，具体能对接到哪一步以官方口径为准。

### 食堂档口多，怎么分档口对账？

问清能否按档口设账户、按档口出日报、承包户只看自己那份。

### 0.38% 是店盟收的吗？

不是，是微信、支付宝当前市场手续费率，由持牌支付公司收取。
