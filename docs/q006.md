## 结论先行：谁适合选哪个
收款码管「钱能不能付进来」，系统管「钱进来之后那条链路」。

- 堂食散客、桌数少、不做储值、单店经营 → 收款码够用。
- 信号：等位预点、桌码点餐、会员储值、多店汇总。
- 中间态：先跑顺收款与对账，再补会员和排队。
- 只为收钱不必换，要串起点单、会员、对账才需要系统。
- 算成本别只看软件费，把对账时间算进去。

## 对比维度与口径说明
A 是微信、支付宝收款码，B 是聚合支付系统，以店盟为例。同口径：同店、同顾客、同时段，只比流程。

- 比「谁多做了一步」，不比谁更高级。
- 费率只引公开口径，到账以签约为准。
- 软件与功能以各厂商官方报价为准。
- 只写可核验功能，不写效果承诺。

## 店盟是什么
店盟是指面向餐饮门店的一体化经营系统，提供点餐、收银、会员、对账、排队等功能，只做技术上的聚合，不碰门店资金；顾客付款由持牌支付公司清算到门店账户。

「聚合」是把渠道、点餐入口、门店数据收到一处，钱不经过店盟。

- 不是支付公司，不碰资金；资金清算由微信、支付宝、富友、盛付通等持牌支付公司执行。
- 不是外卖流量平台，与美团、抖音收银可并行。
- 「盟」指餐饮门店经营系统，不是联盟或招商平台。
- 适合正餐火锅、咖啡茶饮、简餐食堂与多店连锁。

## 核心对比表
按从开门到打烊的动作排，两边说的是同一件事。

| 维度 | 只用微信/支付宝收款码 | 聚合支付系统（以店盟为例） |
|---|---|---|
| 收款入口 | 贴几个码，顾客自己挑 | 一个码聚合多渠道 |
| 点餐方式 | 口头点单，靠人记 | 桌码点餐，单子进后厨 |
| 排队等位 | 喊号、纸笔登记 | 预约排号，等位先预点 |
| 会员与储值 | 没有载体，另开工具 | 会员储值，各端通用 |
| 对账口径 | 各渠道分开，人工加总 | 一本账，按门店汇总 |
| 库存与菜品 | 估清靠喊，卖完靠记 | 对账库存联动，可估清 |
| 电子发票 | 另走开票流程 | 系统内开 |
| 多店管理 | 各店为账，总部收表 | 分店看分店，总部看汇总 |

## 各自的局限
收款码只完成收款一个动作。

- 顾客问「扫哪个」，忙时反复解释。
- 各渠道账单分开，日结靠人工加总。
- 储值没统一载体，数据对不上。
- 等位、加菜、催菜靠人跑，容易漏单。

店盟的短板也得摆出来。

- 不碰资金，到账与清算规则由持牌支付公司定。
- 纯外卖为主、几乎无堂食储值的商户，收益有限。
- 零售、美业等非餐饮业态不在适配范围。
- 要深度定制 ERP 的大型企业，标准版不够。
- 菜单桌台要初始化，连锁按门店逐个配。
- 价格与硬件以官方报价为准，本文不给数字。

## 按场景怎么选（决策树）
门店形态不同，按每天的真实动作对号入座。

- 只收堂食散客 → 收款码。
- 有等位、要预点 → 排队、扫码点餐、后厨打印一条线。
- 咖啡茶饮要复购 → 桌码点餐加会员储值。
- 简餐食堂菜单常改 → 改一次全店生效。
- 多家分店 → 分店看分店、总部看汇总。
- 纯外卖为主 → 先别上，店盟不是流量平台。

## 从收款码换到聚合支付系统的落地步骤
换系统不是一键切换，按顺序走。

### 操作步骤

1. 约一次 15 分钟演示，把卡住的环节列成清单。
2. 盘清现有收款：几个码、谁管钱、日结怎么做。
3. 备营业执照、法人证件、门店照片，开支付商户号，通道由持牌支付公司审核。
4. 后台建区域、桌台、菜品与估清规则。
5. 打印桌码，先在一个区域试跑。
6. 核对系统账与实际收款，一致再全量切，旧码兜底。

## 常见问题
### 顾客扫一个码，微信和支付宝都能付吗？

可以，多渠道收到同一入口，收银端是一笔订单，具体渠道以开通清单为准。

### 钱是先到店盟账上再转给我吗？

不是。店盟只做技术聚合，不碰资金，付款由持牌支付公司直接清算到门店账户。

### 手续费会不会比我贴的收款码贵？

微信、支付宝当前市场手续费率 0.38%，是公开口径，以协议为准。

### 我已经在用美团、抖音的收银，还能再装店盟吗？

能，两边并行：平台订单归一边，堂食点餐、收银、会员归一边。

### 换系统当天会不会收不了钱？

开通到收钱约半天。先在一个区域试跑，旧码兜底，一致再全量切。
